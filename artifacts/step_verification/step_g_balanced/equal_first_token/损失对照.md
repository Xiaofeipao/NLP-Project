# 单步 V 为什么偏向 valid

此前的 `train_gpu.py` 通过 `g_probes.batch_loss` 调用了 `single.batch_loss`。该入口使用每条样本内部的 token 平均交叉熵。五类各有 400 个训练样本，各标签的首 token 都不同。计入 EOS，`valid` 全长 2 个 token，首 token 的损失系数为 1/2。`obstacle_collision` 全长 6 个，系数为 1/6。另外三个标签全长 7 个，系数为 1/7。

旧模型第二轮在开发集的 80 个方向动作中判了 68 次到达，19 次正确。49 次误报包含 18 次撞墙、18 次合法未到和 13 次越界。20 个非法词均识别正确。给定金标准前缀时，五类标签剩下的 480 个 token 全部预测正确，错误集中在类别决定上。把训练 V 的 2,000 条全部回放后，旧模型同样一次都没有输出撞墙或合法未到。

## 只改变 V 首 token 与后续 token 的损失比例

修复后的 `g_probes.batch_loss` 使用 `model_io.batch_loss`，五类均取 0.5 × 首 token 交叉熵 + 0.5 × 其余有效 token 的平均交叉熵。通过实际训练入口的梯度测试可以复现旧版的 1/6，修复版的五类系数均为 1/2。原来的 `valid` 样本已具备这组系数，改动增加了其他四类在首 token 上的监督。

两组均从同一 Flan-T5-base 原始权重开始，在同一台 RTX 3050 上运行，复用相同的 15 个数据文件、随机种子 42、BF16、有效批量 16、学习率 0.0001 和 500 次更新。两组都按开发集选中第 2 轮。表中是模型实际贪心解码的结果。

| 指标 | 原 token 平均 | 首 token 等权 |
| --- | ---: | ---: |
| 开发集判为到达的次数，真实为 20 次 | 68 | 18 |
| 到达召回 | 19/20 | 5/20 |
| 到达精确率 | 19/68 | 5/18 |
| 撞墙召回 | 0/20 | 8/20 |
| 越界召回 | 7/20 | 20/20 |
| 非法词召回 | 20/20 | 20/20 |
| 合法未到召回 | 0/20 | 0/20 |
| 单步 V 正确数 | 46/100 | 53/100 |
| 单步 V 五类宏 F1 | 0.3739 | 0.4617 |
| 开发集 G 最优方向命中 | 66/100 | 60/100 |
| 开发集 G 贪心完整路径成功 | 20/100 | 10/100 |
| 固定单错测试整条判定完全正确 | 93/200 | 23/200 |
| 固定双错测试整条判定完全正确 | 114/200 | 42/200 |

修复版开发集判越界 42 次，真实越界为 20 次。两份固定测试共享的 100 条有效完整路径中，旧模型接受 71 条，修复版接受 8 条，另有 79 条被误报越界、13 条被误报撞墙。逐步验证会在第一个预测的非法动作处终止，因此一次中途误拒就会使一条正确路径失败。

换墙对照揭示了仍然存在的问题。训练集有 80 对固定当前位置、目标和动作、仅交换墙位置的输入，每对的正确输出分别是撞墙和合法未到。旧模型在这 80 对中全部两边都判到达。修复版有 6 对改变了预测，两边都答对的有 0 对。开发集 4 对中，两种模型都未随墙位置改变预测。这次同种子对照显示了损失分配对 `valid` 输出频率的影响，也显示几何条件仍需要模型学会。原始计数、逐轮结果和分支检查见同目录的 `loss_comparison.json`。
