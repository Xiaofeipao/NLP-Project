# 单步 G/V 数据逐项核对

基线为 `StepVerification-v1-v2` 的 `9eeb494f`，上一版指 `data/step_last_move`。本版正式训练用 2,000 条 G 和 2,000 条 V，开发各 100 条。下文依次给出标签与复用、捷径与输入、测试边界、使用与复现。

## 一、G 的同一状态怎样给 V 出题

| 核对项 | 实测结果 |
| --- | --- |
| 最短路有多个正确方向 | 对每条 G 枚举可走邻格并重新计算剩余最短距离。2,000 条的最优集合全部一致。911 个状态有 1 个最优方向，1,079 个有 2 个，10 个有 3 个。训练损失取所有最优方向的概率和。 |
| G 的方向分布 | 用于展示的训练代表动作数为上 500、下 479、左 510、右 511，开发分别为 24、21、22、33。正式 G 继承上一版的状态和完整最优集合，语义正确的并列方向均参与监督。 |
| G 的答案在 V 中代表什么 | 逐条验证 G 的 2,000 个代表动作，188 个一步到达，1,812 个合法但未到。纳入全部并列最优方向后是 188 个到达和 2,911 个合法未到。 |
| 全量复用是否造成偏类 | 每个 G 状态分别尝试四个方向。训练来源的 8,000 条中，5,361 条合法未到，1,325 条越界，1,126 条撞墙，188 条到达，非法词为 0。开发来源的 400 条分别为 266、59、65、10、0。 |
| 正式 V 的类别与方向 | 见下表。400 个到达样本中，188 个用尽 G 自带的到达动作，212 个由同一训练分区的其他状态补齐。20 种训练非法词每种 20 条。开发有 10 种各 2 条，含 5 种训练未见词。 |
| 同一状态换动作 | 正式训练有 1,127 个 G 状态被 1,608 条 V 复用，155 个状态在正式 V 中四方向齐全，125 个同时展示最优动作和可行但非最优的动作。全量检查文件中 2,000 个 G 状态都具备四方向。 |

| V 唯一输出 | 当前动作执行结果 | 正式训练 | 正式开发 | 每个物理方向在训练中的条数 |
| --- | --- | ---: | ---: | ---: |
| `valid` | 合法且到达目标 | 400 | 20 | 各 100 |
| `goal_not_reached` | 合法，尚未到达 | 400 | 20 | 各 100 |
| `obstacle_collision` | 目的格被墙占据 | 400 | 20 | 各 100 |
| `out_of_bounds` | 目的格越界 | 400 | 20 | 各 100 |
| `invalid_action_token` | 输入词不属于四方向 | 400 | 20 | 按非法词计数 |

原 V2 的 2,000 条直接 V 中有 1,589 条到达，合法未到为 0，另有 2,000 条 G 上的辅助停止监督均为未到。本版的 400 个未到标签全部由真实合法动作产生。正式开发的前四类每个方向各 5 条。

真实训练样本 `train-2291` 的当前位置是 `(4,5)`，目标是 `(5,5)`，唯一墙格是 `(3,5)`。四条 V 共用同一段状态，`down` 到达，`left` 合法未到，`up` 撞墙，`right` 越界。每次只问一个动作。

## 二、模型能否靠格式或固定路径猜中

| 核对项 | 实测结果 |
| --- | --- |
| 训练、在线、离线 V 问法 | 同一函数渲染任务、网格约定、当前位置、目标、墙、合法词表、最后一个动作、输出要求。13,986 条训练、开发及诊断记录全部通过分词检查。其中 11,886 条 V 的在线输入与落盘输入逐字一致。所有 V 输入只有一个非空动作词，真实动作之外的拼写可以作为非法候选。 |
| 模板位置、标点和标签泄漏 | 所有 V 共用一个模板骨架和标签顺序，坐标从零起算，墙格排序固定。正确答案写在单独的训练目标字段。最优方向集合、是否训练过、来源 ID 和错误步号只存于元数据。原 V2 的 2,000 条直接 V 只有 1,907 个不同输入，本版正式训练与开发各自的重复输入和同输入标签冲突均为 0。 |
| 精简是否损失约束 | 在同一批训练状态上用 Flan-T5-base 分词器比较。G 平均输入由 V2 的 166.92 降至 64.65 个 token，V 由 190.69 降至 107.62。相对上一版，V 增加的 8 个 token 明确列出合法动作。全部输入最长 113，标签最长 7，输入未知 token 和截断均为 0，标签全部可精确解码。 |
| 固定词、长度与墙数 | 在开发集的 100 条 V 上，只看模板猜对 20 条，只看动作词猜对 30 条，只用文本长度、动作长度和墙数猜对 24 条，用动作和墙数猜对 27 条。训练非法词从单一 `jump` 扩至 20 种。查四词词表能识别非法词，按坐标和方向计算能识别越界，均符合标签定义。 |
| 模型能否绕过墙的位置 | 保留动作、起点、目标和边界，遮住所有墙，规则仍能答对 80/100，撞墙召回为 0/20，宏 F1 为 0.7333。40 组训练对照固定起点、目标、动作和墙数，只交换墙的位置，遮墙规则只能答对 80/160。开发对应 4/8。另有只改目标、目的格障碍、边缘位置的训练对照各 20 组。 |
| 最短路最后一步的横纵偏差 | 只统计原起点、原目标都固定且两种轴向都能最短到达的样本。V2 归档是横 941、纵 3。上一版训练为横 89、纵 27，本版为横 100、纵 100，四方向各 50。99 组原地图与起终点实际同时展示了两种到达方式。上一版开发为横 7、纵 1，本版各 5，有 3 组同图双向。 |
| 绕行、非最短有效路径、循环 | 531 个训练 G 状态必须先增大曼哈顿距离才能走最短路，V2 归档有 177 个。无视墙的“先横向靠近目标”在训练 G 只命中 1,346/2,000，在开发命中 68/100。2,000 次参考最短路回放均成功且无重复格。额外抽查折返、绕方格和无重复格绕行各 20 条，参考 V 均接受。 |

V2 归档里，一条只看空输入和 `jump` 的规则可复现 500/500 条模型输出。该数字衡量规则与旧模型的一致性。上表的规则分数衡量它们与参考答案的一致性。旧模型在固定单错测试生成失败的 20 个案例均反复在两个格子间来回。新模型实际会不会循环、能否识别墙，要在微调后按类召回和完整路径测量。

按此前三个分支的训练数据核对，固定当前位置、障碍和动作，只改目标便让到达标签翻转的组数分别为 V2 的 0 组、`codex/newpart1-prompt-shortcut-study` 的 1 组和 `Part2-Part3` 的 3 组。只改目的格障碍、令可走与撞墙翻转的组数均为 0。本版专门保留这两种训练对照各 20 组。

## 三、路径验证、数据来源与评估边界

| 核对项 | 实测结果 |
| --- | --- |
| 生成、首错与回撤 | 训练模式只有 `g_next`、`v_step`。在线生成时，前缀已验证，本步 `valid` 即可输出，`goal_not_reached` 则推进位置。对给定的整条候选，程序拆成连续的“动作前状态 + 一个动作”，逐步调用 V，按首个非法动作报错。若所有动作合法而终点未达，按原项目约定报动作数加一。空路径由程序处理。回撤和重选归外层程序。 |
| 与原始执行器核对 | 原始单错、双错测试各 200 条，文件 SHA-256 与 V2 相同。按正确的单步标签回放，整条判定、首错步号、原因共 400/400 完全一致。其中 4 条空路径有整条判定。非法词按项目严格四词词表处理，原版执行器本身会跳过未知词。 |
| 环境与训练预算 | 按障碍布局切分，训练 652 张，开发 76 张，两份测试各 79 张。训练、开发与测试之间的布局交叉和受监督输入交叉均为 0。两份原测试共用 79 张测试布局和 100 条相同的有效候选。正式训练 4,000 条，正式开发 200 条。训练地图均为 6×6，障碍数为 1–5。 |
| G 来源的全量与平衡检查 | `diagnostics/g_train_four.jsonl` 的 8,000 条和 `g_dev_four.jsonl` 的 400 条均保存 G ID、方向和该方向是否最优。分别有 1,208、60 条也属于本分区正式 V，已经逐条标记。五类平衡诊断各 188 条、各 10 条，非法词取自相同分区的 G 状态。训练来源仅用于复查，正式模型选择使用冻结的 200 条开发记录。 |
| 测试上的单步与整条分数 | 测试局部文件从原候选选首个非法动作或最后一个真实动作。单错局部 196 条，195 个不同输入。双错局部 200 条，199 个不同输入。相同输入的答案一致。去重后的可选平衡子集分别为每类 8 条、11 条。局部观察步由参考答案选定，首错定位要用两份完整的 200 条路径评分。 |
| 固定测试能测到哪些错误 | 两个固定测试各有 100 条正确路径，最短和可行非最短各 50 条。另外 100 条分别含一次、两次独立编辑。双错标签取执行顺序中的首错。固定测试的非法词只有 `jump`，对训练未见拼写的检查使用开发集的 10 条对应记录。7×7 和更密障碍的泛化未在本次核对中测量。 |

两次独立构建及工作区副本的 15 个数据文件逐字节一致。19 项单步接口与工作流测试、18 项网格和策略测试均通过。新增测试通过实际训练入口反向传播，逐类核验首 token 的梯度系数。CPU 用随机小型 T5 读取全部训练特征，并执行了单步解码。

RTX 3050 上的两轮同配置对照中，统一首 token 权重后，开发集 V 判为 `valid` 的次数由 68/100 降至 18/100，五类宏 F1 从 0.3739 升到 0.4617。合法未到的召回仍为 0/20，固定单错、双错测试的整条判定均下降。逐类预测和完整路径的结果见包内 `outputs/step_g_balanced/equal_first_token/损失对照.md`。

## 四、文件与运行方式

将交付包解压到上述 V2 分支的根目录。正式训练、开发和冻结测试在 `data/step_g_balanced/`，所有派生检查文件在其 `diagnostics/` 子目录。可在 `audit.json` 查看逐类和横纵计数，在 `shortcut_audit.json` 查看逐类召回、精确率和宏 F1，在 `control_groups.json` 查看配对样本 ID。`manifest.json` 记录原始数据、执行器、分词器和模板指纹。

```python
from step_data_v3.g_probes import prepare_training, batch_loss, verify_last, verify_plans

features = prepare_training(runner, "data/step_g_balanced")
# DataLoader 使用 runner.collate，训练循环用 batch_loss(runner, batch)。
label = verify_last(runner, state_before_last, last_action)
path_verdicts = verify_plans(runner, grids, candidate_paths)
```

沿用 V2 的 Flan-T5-base 接口，配置 `policy_loss="optimal_actions"`。G 的损失为所有最优方向概率之和的负对数。V 的五个标签有不同的首 token，训练时首 token 的交叉熵占 50%，其余有效 token（含 EOS）的平均交叉熵占 50%，混合批次按样本平均。训练加载器只读正式训练集。模板指纹和 V 损失公式写入 checkpoint 配置。给定完整路径时使用 `verify_plans`，在线验证单个提议用 `verify_last`。

独立五分类实验从同一份 Flan-T5-base 预训练权重开始。V 对编码器的有效输入位置取平均，用一个线性层输出到达、合法未到、撞墙、越界和非法动作词的五个分数，每条样本算一次交叉熵。G 沿用最短动作集合损失。以下命令跑三个完整 epoch，每轮保存开发集预测，按开发集 V 宏平均 F1 选 checkpoint。

```powershell
python -m step_data_v3.train_gpu --data data/step_g_balanced --pretrained $pretrained --out outputs/five_class_trial --verifier-head --epochs 3
```

加载五分类 checkpoint 使用 `step_data_v3.five_class.FiveClassRunner(checkpoint, config)`。单步和固定路径推理继续使用 `verify_last` 和 `verify_plans`。类别顺序随权重保存在 `config.json` 的 `ppnl_verifier_labels` 中。

已有上一版 `data/step_last_move` 时，运行下列命令重建。将两个本地路径换成项目原始执行器与 Flan-T5-base 的 `tokenizer.json`。从干净的 V2 首次复现时，先按顺序运行 `step_data_v3.build`、`step_data_v3.prepare_single`、`step_data_v3.paired_steps`，各传入 `--executor $executor`，并依次把 `--out` 指向 `data/step_semantic_v3`、`data/step_semantic_single`、`data/step_last_move`。

```powershell
python -m step_data_v3.balance_steps --executor $executor --tokenizer $tokenizer --out data/step_g_balanced_rebuilt
python -m step_data_v3.validate_g_balanced --data data/step_g_balanced_rebuilt --tokenizer $tokenizer
python -m unittest step_data_v3.test_g_probes step_data_v3.test_last_move step_data_v3.test_single state_baselines.test_step_verification state_baselines.test_workflow
```
