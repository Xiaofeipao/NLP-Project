# 实验协议

## 数据和错误

只使用固定版本 PPNL 官方单目标 6×6 world。对所有来源重新按障碍物布局分组，80% 左右训练、10% 开发、10% 测试；原始文件名中的 train/test 不直接作为本研究 split。重新划分的 ID 和来源记录在 manifest 中，报告须说明这一点。

过滤不可达及最短路径小于两步的环境，确保可进行双位置错误注入。BFS 重建并经官方校验的最短路径是修复目标。合法非最优路径在起点添加一个合法的往返动作，长度比最优路径多两步。该构造简单且受控，应作为局限性报告。

单错误类型包括替换、删除、插入、提前停止和未知动作 token。提前停止算一次截断操作，可能移除多步。OOD 两个操作独立选取不同原始位置，以替换/删除/插入/未知 token 构造，要求最终 token Levenshtein 距离为 2；避免两个操作相互抵消。操作后仍然成功的负例被丢弃重采样。两个注入错误不保证执行器能观察到两个失败，因为执行在首次失败时停止。

数据包含错误操作记录和实际首个失败类型。操作配额不等于失败类型配额；manifest 会报告实际各类样本数。某类缺失或过少时，应在报告披露，不能编造分类指标或偷偷利用测试集反复调配额。

三个训练任务总共 4,000 条，多任务共同训练，每种任务不单独重复训练模型。开发 200 条，测试各 200 条。训练数据中的多个任务可能使用同一训练环境，这是允许的；split 间禁止同布局泄漏。

测试集保留合法控制样本用于 Macro-F1；因此 OOD 的“两错误”限定在非法候选子集，而非合法控制组。ID/OOD 配对测试起终点，避免网格难度混淆。候选修复的 OOD 泛化才衡量错误数量迁移。直接生成和从直接生成开始的端到端评估不读取预设候选，因此在相同测试网格上，ID/OOD 这部分指标预期相同，不应把它包装成两次独立的网格泛化证据。

## 指标

- Success Rate：最终执行位置为目标，且整个动作序列没有违法移动或语法错误，分母为全部被评估路径。
- Feasibility：所有动作合法、无越界或碰撞，分母为全部路径；不要求到达目标。
- Optimality：成功且动作数等于 BFS 最短路径动作数，分母为全部路径。
- Path Efficiency：仅在成功样本上统计最短动作数/输出动作数，作为补充指标。
- 验证 Macro-F1：固定 valid/invalid 两类取平均；不符合输出格式的预测算对应真类的漏报，不能过滤出分母。
- 首错定位准确率：在全部金标非法候选上，预测 invalid 且首错步正确的比例。
- 错误类型准确率和首错联合准确率：分别检查原因，以及原因与步数同时正确。
- Repair Success Rate：全部金标非法候选中，经修复后成功的比例。
- End-to-End Success Rate：对唯一布局/起点/终点组合，直接生成及完整管线最终成功的比例。

首次失败步采用从 1 开始的动作索引。没有碰撞但执行完仍未到目标时，失败步为动作数量加一，即 EOS；空路径对应第 1 步。非法动作位于物理失败之后时，以更早的物理失败为首错。

失败类型分组结果分别来自候选金标原因、直接生成路径的实际原因。单一原因组的二分类 Macro-F1 仍采用固定两类，因此不应与总体 Macro-F1 混淆；定位和修复指标更适合在这些组中比较。空组/无成功组的指标保存为 null，而不是伪造为 0。

## 改进与消融

改进为最多三轮执行器引导的迭代修复。每轮重新执行当前完整候选，仅修复仍失败的路径；一旦成功则保持该输出。消融去掉重复修复，只允许第一轮，等于一次执行器反馈基线。所有比较使用同一个主模型 checkpoint，无额外训练样本或训练轮数。

这是一个推理计算量增加的改进，不能宣称与一次修复具有相同推理预算；报告应结合 GPU ledger 和实际尝试次数讨论成本。执行轨迹保存每轮输出和反馈，便于分析只修复第一错、引入新碰撞、未达到目标、过长合法路径等案例。

自验证管线仅在模型精确输出 `valid` 时跳过修复；模型输出非法格式时，保留原始反馈文本并触发一次修复。真实执行器仅用于最后计分，不参与自验证管线的决策。

## 预算与选择

一个固定 seed。两个基线的数据、batch、学习率、正式训练轮数及 pilot batch 数相同。pilot 是一次部分数据遍历，正式训练默认两轮，总计不超过三次。没有设计测试集调参。开发集统一规则选择主模型，selection 文件冻结后才能跑测试。

20 GPU 小时是上限，不是已测时长或保证能跑完的承诺。所有 GPU 命令必须串行使用同一 ledger；ledger 不是分布式调度器，不支持并行写入或跨机器自动汇总。CPU 数据构造时长单独记录。GPU ledger 包含加载、训练、验证、推理和保存阶段的墙钟时间；在 batch 边界检查预算，异常也记录。
