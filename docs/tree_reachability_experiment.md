# 决策树验证与无解诊断实验

实验分支：`tree-verifier-reachability`，从 `86b52ed` 分出。main 的训练、推理默认逻辑不变。本分支不是新的 LoRA 或 GRPO 模型：它增加 CPU 决策树验证器，并复用冻结的语言模型做 GPU 推理对照。

## 代码与数据

- `tools/run_tree_verifier.py`：使用原有 2,000 条 V 训练候选，展开为 10,380 个动作状态。特征为坐标、动作和障碍位图，训练标签由执行器产生；推断不调用执行器获取答案。深度从 4、8、12、不限中按开发集选择，最终为 8。
- `tools/run_tree_reachability_gpu.py`：三个全量微调基线和三个逐步策略测试八例地图；另用固定 T5-base 修复器比较树、语言模型 V、执行器三种诊断。只修一次，误报 valid 时保留原错误候选。这里没有重新训练语言模型。
- `tools/reachability_probe.py`：四对只差一格的可达/不可达地图，严格检查 NO_PATH；奖励函数以 BFS 为真值，正确拒绝或合法到达得 +1，其余 -1。
- `tools/prepare_reachability_feedback.py`：额外生成 16 条训练候选、8 条开发候选，与原数据和八例诊断布局隔离。偏好、标注者及理由均留空，尚不能作为真实人类反馈训练。

原 G800/V2000/R1200 配额保持不变。待标注数据没有并入训练；未来加入训练前必须重新分配总配额和冻结划分。八例公开地图永久用于诊断，不用于训练或调参。奖励函数目前是独立接口，尚未接入 GRPO 优化步骤，不宣称完成了新 RLHF/RLVR 训练。

## 决策树结果与边界

ID 200 例分类 Macro-F1 为 1.0，OOD 200 例为 0.995；两组首错位置与错误类型联合准确率均为 86%。这是结构化特征加状态更新的传统学习验证器，不能当作语言模型自验证，也不能替代题目要求的语言模型与执行器反馈对照。

测试集为历史复用测试集，结果属于探索性消融。即使分类分数高，也必须以固定 R 的修复成功率判断实际用途。完整预测与 GPU 结果保存于 `outputs/tree_verifier_001`、`outputs/tree_reachability_gpu_001`，可分享副本在 `docs/experiments/tree_reachability/`。

## 复现和保留原则

当前完成状态（2026-11-05）：三个模型 GPU 诊断和固定 R 对比均已完成。直接生成可达成功均为 0/4；T5-small、T5-base、BART-base 的逐步 Harness 分别为 4/4、4/4、3/4。明确无解识别全部为 0/4，可达误拒全部为 0/4。

固定 T5-base R、一次修复、相同非法候选：树/执行器/模型 V 的开发集成功数均为 11/60，ID 为 24/24/21（分母 100），OOD 为 5/6/3（分母 100）。不能与生成后端到端修复的 200 环境成功率直接比较。开发集无改善，因此保持原默认方案，树作为低成本对照保留。

启动排查中，隔离模式解释器输出正常，随后使用 PowerShell 显式调用解释器成功完成运行。进程枚举对 GPU 进程显示权限不足，故之前“看不到 Python”不足以证明解释器故障。未发现需要重装 Python 或 CUDA 的证据。脚本现增加启动、模型加载和分组进度输出，避免长时间无输出被误判为启动阻塞。

在已安装项目依赖的环境中安装 `requirements-experiments.txt`。先恢复归档中的六个模型 LFS 权重，再依次运行上述 tree verifier 和 GPU 脚本。CPU 训练拒绝覆盖已有输出；GPU 脚本跳过已有完整模型报告。中断后留下的不完整 session 应先归档，再重新运行，不能覆盖轨迹。

不根据这八例或重复测试集升级默认方案。不改善修复或未具备 NO_PATH 能力的方法保留为负结果消融；稳定 main 不受影响。回到 main 即可恢复原有项目入口，无需删除失败证据。
