# 逐步策略规划改进

本次改进已完成训练和评估。原始两个基线及其测试结果保持不变；新模型、数据表示和结果放在独立目录。代码运行于 torch_py311 和 RTX 5060 Ti 16GB。

## 问题证据

原 Flan-T5-small 在 98 个开发环境中仅输出 3 种规划，72 次重复 `up up up up up right right right right right`。它的直接生成成功率为 0%，尽管验证和部分候选修复已有一定效果。这支持将整条序列预测改为显式状态条件下的下一动作学习，而不是仅增加修复轮数。

## 训练修改

`ppnl/policy_data.py` 从原有训练集逐行改写数据：对 800 条生成样本和 1,200 条修复样本，各随机抽取其正确目标路径上的一个位置，监督下一步动作；保留全部 2,000 条验证样本。每个原始 example ID 和 source ID 都保留一条对应记录，没有将一条路径展开成大量额外样本。开发集同理为 100 条下一动作和 100 条验证监督。

输入显式描述当前位置、目标位置、由两者坐标计算的相对方向、当前合法动作和二维字符网格。训练标签来自原有正确路径；推理输入不包含该路径、剩余最短路、BFS 距离或参考动作。精确状态跟踪和局部合法动作来自模拟器，因此这是一种带结构化状态观察的改进方法，不能称作原始的一次性自然语言生成。

重新微调开发集选定的主模型 Flan-T5-small，从相同固定版本的原始预训练权重开始，而非继续使用旧基线权重。保持 seed 42、4,000 行、两轮、batch 8、梯度累积 2、学习率 1e-4，共 500 次更新。两轮开发集 loss 为 0.2634 和 0.2021。额外训练计入同一个 20 GPU 小时账本。

新权重在 `outputs/planning_v2/flan_t5_small/train/best/`，配置在 `config.policy.json`，全部测量和校验在 `outputs/planning_v2/results.json`。

## 推理方法和消融

`ppnl/policy.py` 的 NeuralPolicy 一次前向只取首个 decoder 位置上 up/down/left/right 四个 token 的分数，不自回归生成整条路径。四个动作在已确认的 Flan-T5 tokenizer 中各为一个 token；其他 tokenizer 不满足条件时直接报错，不默默错误打分。按网格布局、目标和当前位置缓存状态评分，各环境共享批处理。

- `state_policy`：按模型分数选择动作，执行后更新状态；不使用移动合法性 mask，也不搜索。到目标时由状态跟踪器停止，越界或碰撞则记录失败，最多 36 步。
- `legal_mask_no_search`：同一个模型，仅允许合法且本路径未访问的下一状态。可能陷入死路，陷入时记录未到目标，不调用最短路径兜底。
- `neural_best_first`：用动作负对数概率、步数和 Manhattan 距离排序的图搜索。每个格子最多展开一次，上限 36 个状态；超限时返回失败。权重固定为 0.25，没有按测试集调参。它不是保证最短路径的纯 A*。
- `symbolic_astar_no_model`：不调用模型的 A* 对照。必须保留它，才能区分神经策略和符号搜索的贡献。

在开发集上按成功率、再按最优率选部署方法，测试前冻结权重 SHA256 和开发集指标文件 SHA256。选中 neural_best_first；所有其他方法仍完整报告作为消融。

## 实际测试结果

在原来的相同 200 个 ID 网格起终点上：

- 原始整序列生成：成功率 0%。
- 逐步神经策略，不加移动约束或搜索：成功率 76%，最优率 76%。
- 合法动作约束，不搜索：成功率 95%，可行性 100%，最优率 85.5%。
- 神经引导图搜索：成功率 100%，可行性 100%，最优率 99.5%。
- 纯 A*：成功率 100%，最优率 100%。

神经引导搜索平均展开 5.165 个状态，纯 A* 为 8.26 个，减少约 37.5%。这不等于墙钟加速：神经网络需要 GPU 推理，纯 A* 在这样的小网格上很便宜。各方法共用状态评分缓存，metrics 中的时间是增量耗时，不能直接当作独立冷启动速度比较。纯 A* 的最优率略高于神经引导搜索，也不能宣称学习方法全面优于 A*。

## 保留合法前缀的修复

先由执行器保留候选中实际执行成功的前缀，首次失败动作及其之后的内容丢弃，再从当前状态重新规划后缀。如果执行过程中已到目标，就可直接截断后面的错误。这利用了明确的符号反馈，与旧模型的一次性全文修复任务不同，不能把提升全部归功于模型权重。

在 100 个非法 ID 候选上，逐步策略续写、约束续写、神经搜索续写的成功率分别为 86%、97%、100%；纯 A* 续写也为 100%。在 100 个非法 OOD 双错误候选上，分别为 86%、96%、100%，纯 A* 仍为 100%。保留前缀可能保留不必要的绕行，故搜索续写的整体最优率只有 ID 74%、OOD 70%。

ID/OOD 原本就是同一组网格、不同错误候选，所以从零规划的指标相同；只有候选修复实验体现错误数量迁移。未测试更大网格或多目标环境。

## 使用

```powershell
conda activate torch_py311
python scripts/plan_grid.py --grid examples/grid.json
python scripts/plan_grid.py --grid examples/grid.json --method state_policy
python scripts/plan_grid.py --grid examples/grid.json --method legal_mask_no_search
```

默认读取开发集已冻结的部署方法。输入可为单个 world 矩阵、含 world 字段的对象，或 rows/cols/obstacles/start/goal 对象。示例来自开发集，不是新增训练样本；默认方法实测输出 `left left down left left`，执行成功。

重新完整训练时，在新配置中使用新的 output_root 和 dataset_root，再运行：

```powershell
python scripts/run_policy_study.py --config config.policy.json
python scripts/summarize_policy.py --config config.policy.json
```

现有配置直接重跑会复用已完成阶段；配置不同则拒绝复用，避免将旧指标当作新实验。训练、评估和示例调用都记录到共用 GPU ledger。

## 验证和解释范围

22 项测试通过，覆盖状态更新、动作重复、物理 mask、失败时不调用隐藏最短路、绕墙搜索、搜索预算耗尽、前缀修复和原有执行器对照。原始基线权重 SHA256 保持不变，测试候选逐字节不变，训练/开发的 example ID、source ID 和布局对应关系保持不变。所有生成规划和修复规划都与官方 is_goal 核对。

本轮只有一个固定配置和一个 seed；原测试集的总体差成绩在改进前已知，因此这是复用测试集上的方法改进评估，不是全新盲测。没有利用逐个测试标签训练或调参。76% 表明结构化逐步策略在本任务上学会了有用的动作决策；100% 的可靠性来自模型与符号搜索的组合，纯搜索对照说明不能把它宣称为语言模型独立推理达到 100%。
