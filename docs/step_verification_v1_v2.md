# 逐步验证 v1 与双标签 v2

两个版本从同一 Flan-T5-base 预训练快照分别做全量微调。每版训练两轮，每轮 4,000 条记录，共 500 次优化器更新。两版都按原开发集规则选中第二轮。固定候选由原开发、单错 ID 和双错 OOD 数据提供。两份旧 G 的固定轨迹另用于控制生成端的差异。

| 版本 | G 训练监督 | 独立 V 训练监督 | 入口参数 |
| --- | --- | --- | --- |
| v1 | 原 2,000 条下一步动作 | 原 2,000 条候选各取一个局部观察，保留 1,000 条 `valid`、589 条未完成和 411 条动作错误 | `--step-train` |
| v2 | 原 2,000 条下一步动作，每条另加当前位置停止的 V 标签，辅助损失权重 0.5 | 1,589 条 `valid` 和原 411 条动作错误。增加的 589 条 `valid` 取自同网格参考路径的到达步 | `--dual-train` |

逐步 V 输入动作执行前的坐标、地图、目标和单个候选动作。程序维护当前位置并将局部判断换算为全局步号。模型报未到目标但还有动作时继续检查，报其他错误时在当前步停止。V 文本沿用 NewPart1 的拆分损失。[任务输入输出与案例](step_verification_cases.md)

| 固定候选 | 原 NewPart1 Macro-F1 | v1 Macro-F1 | v2 Macro-F1 | v1／v2 有效误拒 | v1／v2 无效检出 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 开发，100 条 | 66.93% | 45.24% | 58.64% | 43/50、0/50 | 47/50、14/50 |
| ID 单错，200 条 | 68.54% | 37.75% | 55.59% | 91/100、0/100 | 84/100、24/100 |
| OOD 双错，200 条 | 72.22% | 39.59% | 73.33% | 91/100、0/100 | 90/100、50/100 |

ID 与 OOD 共用 100 条有效路径。v1 的 91 次误拒均为碰撞误报。v2 正确定位并识别 65 条首错为非法动作词的测试路径，漏掉全部 84 条非空且动作全合法的未完成测试路径。对测试中 28 条首错为碰撞、19 条首错为越界的路径，v2 的正确类型数均为 0。

| 候选来源 | v1 模型 V＋规则修复 | v2 模型 V＋规则修复 | v1／v2 执行器 V＋同一规则 |
| --- | ---: | ---: | ---: |
| ID 固定候选 | 133/200 | 114/200 | 180/200、180/200 |
| OOD 固定候选 | 133/200 | 126/200 | 166/200、166/200 |
| ID 各自生成 | 171/200 | 180/200 | 179/200、187/200 |
| 固定 FirstPart G | 172/200 | 169/200 | 180/200、180/200 |
| 固定原 NewPart1 G | 179/200 | 179/200 | 184/200、184/200 |

两版在 ID 各自生成的直接成功数分别为 168/200 和 180/200。模型 V 与执行器 V 使用同一个规则修复器，最终成功由执行器评分。

按 [复现入口](../state_baselines/README.md) 生成两版训练数据，分别指定输出目录执行 `audit`、`train`、`select` 和 `evaluate`。也可从 [实测证据包](../deliverables/step_verification_v1_v2_evidence.zip) 解出原 GPU 运行使用的 `v1/train.jsonl` 和 `v2/train.jsonl`。包内含数据构造审计、训练记录、选模清单、逐例预测、固定生成轨迹和 v2 的开发集状态对照。选模清单绑定当时的检查点 SHA256，模型权重由复现训练生成。v1 的历史运行入口也单独归档，统一入口复现时会为新运行生成新的选模清单。
