# GVR 候选 GPU 实跑结果

已按 `config.gvr.next.json` 完成 G → V → R 的 pilot、两轮正式训练、重载检查、开发集及 ID／OOD 评测。训练前 69 项测试通过；运行中修正 Windows 快照文件占用问题后，72 项测试通过。结果均经过独立 CPU 重算核对。完整数据见 [机器可读记录](gvr_next_run.json)。

## 训练与选模

- generation：处理 1600 次样本、100 次更新；实际学习率 0.0001，选中第 2 轮。
- verification：处理 4000 次样本、250 次更新；实际学习率 0.001，选中第 2 轮。
- repair：处理 2400 次样本、150 次更新；实际学习率 0.001，选中第 1 轮。

修复第 1 轮开发集成功率 15%，第 2 轮下降到 8.3%，尽管第 2 轮 loss 更低，任务指标选模仍保留第 1 轮。验证第 2 轮开发集 Macro-F1 为 0.6624；自定义验证损失与旧 token 损失不能直接比较。

## 结果解释

验证器在固定候选上已不再只输出 valid，但对生成器实际输出的失败路径仍有严重误判。直接生成、自验证修复、执行器单轮／三轮修复的端到端成功率仍为 0%。这轮改善集中在固定候选的验证指标，尚未解决整体规划失败；保留原逐步 Harness 作为独立方案。

本次调整同时涉及目标、学习率、选模和控制器版本。已有测试结果曾用于分析失败和设计候选，因此这些复用测试结果属于探索性对比，不是全新盲测，也不能单独归因于 LoRA 或首 token 损失。ID／OOD 规划网格配对，固定候选的错误不同，不能把两组生成成绩当作独立网格验证。

## 中断与恢复

ID 评测中，进度监控读取 Windows 状态快照，与原子替换发生文件占用竞争。已将监控改为读取权威日志，并为权限占用导致的快照替换增加有上限的重试；永久错误仍抛出且保留原文件、临时文件和已落盘日志。

从原目录复制并校验了 548 个会话，其中 1 个从中断状态继续。完成的会话没有重发模型请求；固定候选阶段重新推理并记录，是否与首次预测逐字相同见 JSON。ID 最终目录为 `outputs/gvr_next/evaluation/test_id_resume/`；原 `test_id/` 保留失败证据。失败操作和续跑操作均计入同一账本，恢复后的时延不作严格性能对照。

共享 GPU 占用账本：本轮增加 0.565 小时，累计 2.423／20 小时。
