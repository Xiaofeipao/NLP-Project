# 回溯与反馈消融：GPU 开发集结果

2026-11-11，入口 scripts/run_gvr_optional_development.py。固定同一历史 Flan-T5-small checkpoint，仅做推理，不训练新权重。原开发集 40 个 G 环境和 60 个合成错误候选；各方法共用每例初始路径和执行器真值，一次修复。没有读取 ID/OOD 测试集。协议、源码哈希、逐例输出和汇总见本目录 JSON。

## 实际结果

40 个真实生成环境：普通修复 0/40；原约束 beam 36/40；回溯配原反馈 39/40；回溯配空反馈或通用反馈均 40/40。约束 beam 配空反馈为 37/40，配通用反馈 36/40。所有搜索组最优率均为 35%，回溯提高可达成功，没有改善最优率。

60 条合成错误候选：普通修复 10/60；beam 和回溯配原反馈均 60/60；配空反馈均 59/60；配通用反馈均 60/60。回溯在该任务没有新增成功。原反馈组最优率均 95%。

同上限不等于同实际计算：每例最多 148 个评分行。生成任务中 beam 原反馈实际 3024 行、35340 decoder 输入 token、12.59 秒；回溯原反馈 5920 行、92486 token、29.08 秒。候选修复对应 4380/8880 行、49885/134851 token、17.55/42.99 秒。时间只计 R 阶段，非总实验墙钟时间，不据此宣称同计算量更优。

## 结论与边界

回溯在开发集能减少死路，但约增加一倍评分行和更多 token。移除具体反馈仍有高成功率，支持“搜索与状态约束贡献很大”的解释，不能断言模型完全不使用反馈：空反馈在合成修复上损失 1 例。40/40 只是开发集结果，不是 200 环境测试成绩，也不是模型训练取得的新能力。

目前保留为可选消融，不升级默认方式，不基于这些数值反复修改测试配置。下一步若评估测试集，需先固定方法和预算、建立新测试冻结。新增四项 CPU 边界测试已通过；历史未运行说明被本报告覆盖，但本轮没有重跑完整回归。

方法实现沿用 Ponytail 的复用原则：共用 Seq2Seq、执行器、指标和预算账本，未引入训练框架或新模型。未重新训练，因此没有新的模型权重。
