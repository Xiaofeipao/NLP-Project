# 七类改进方法开发集选优协议

本轮只在本地执行，先固定方法矩阵，再用开发集选择，最后运行同一矩阵的 ID/OOD 并保留全部结果。用户要求尝试所有可行方向，解释为课程列出的每类方法提供一个有预算边界的代表方案，不代表穷举所有提示、模型和超参数。

## 七类与具体实现

1. 结构化状态跟踪提示：给模型网格字符表、起终点、候选及逐步跟踪指令，不提供真实状态轨迹或诊断答案。
2. CoT 提示：要求输出简短位置推演及 `FINAL:` 诊断；不合格式作为失败保存，不伪造推理过程。另有 tool_trace 对照，由执行器提供压缩的状态观测；该组明确含符号答案线索，不当作独立语言推理。
3. 迭代修复：最多三轮，每轮最多12个新增动作，累计最多36；普通一轮为36个新增动作。额外验证调用单独计数，不能称同GPU计算量。
4. 验证器引导解码：策略提出前两个动作，由一步执行检查过滤非法提案，再以模型分数选择；不是学习式V的额外推理能力。
5. 受约束动作解码：合法动作过滤、合法动作加最少访问次数两种代表。没有图搜索、BFS/A*补路或S捷径缩短。另设移除R模型评分的uniform控制。
6. 多任务目标：已有联合策略/验证模型之上，额外一轮验证训练，增加首token合法性分类辅助损失，保留完整诊断文本损失。
7. 训练输入表示增强：额外一轮验证训练，使用结构化地图提示；地图、起终点、候选和标签不变，不新增合成候选或双错误训练。它仅覆盖表示增强这一种增强方式。

## 训练与样本限制

从同一两轮Flan-T5-base权重独立分出三支：普通文本损失追加训练控制、分类辅助损失、输入表示增强。每支仅遍历原2,000个V样本中未在pilot额外出现的1,984条一次。首16条V在pilot用过，已达三次呈现，因此不继续训练。每个候选谱系最多三次呈现；三个独立候选的计算量全部计入同一账本，不能把独立分支声称只有一次总训练成本。

固定float32、microbatch4、effective batch16、学习率1e-4、seed42，不根据本轮开发或测试调参。控制支确保不会把多训练一次的收益误归因于辅助损失/表示增强。G与R始终使用原冻结权重；训练支只替换V，避免生成模型差异影响比较。

不创建新逻辑训练样本；原4,000训练、200开发和布局划分保持不变。若课程把不同提示视图也计作额外训练样本，最终需向负责人确认该口径，不应以相同ID掩盖额外样本。这里的同ID确实对应完全相同的网格、候选和目标，而非换题。

## 选优与保留

固定21个配置。开发生成使用原200开发记录的191个唯一环境，候选用100条V记录。按开发端到端成功率、原无效候选修复成功率、端到端最优率、验证首错联合准确率依次排序，并列保留矩阵中更早的简单方法。选出的研究改进不包括标记control的纯规则/追加普通训练对照，所有控制组仍公开比较；若控制组更好，必须明确说明，不宣称研究方法优于控制。测试不用于重选。

方法与代码、数据、权重哈希在GPU调用前写入 `outputs/seven_methods/run_001/protocol.json`。训练结束后只看开发结果产生 `selection.json`，然后评测全部固定方法，保存负结果。ID/OOD共用地图，因此仅ID计算一次端到端生成；两种错误候选分别测试。所有结果仍为重复使用测试集上的探索性证据。

保留全部checkpoint、失败和预算记录；“保留最好”表示明确保存开发选中的方法配置，不删除研究证据，不覆盖旧冻结实验或旧全局默认入口，发布不包含权重。
