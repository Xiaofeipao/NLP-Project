# 原 Part2 普通续走 R 的回退实验

本轮明确固定原Part2普通贪心R：同一动作模型，不加Top3、不加访问/循环惩罚、不删环。CPU完成，扫描0至36所有回退步数。模型反馈与执行器反馈分开，开发集选步数，测试不重选。

## 与此前增强 R 的区别

此前Top3+软惩罚+删环的95.5%最优率属于增强R，并且开发选择36步已经是从起点重新规划；不能当成原Part2 R的结果。本报告只研究普通R改变恢复位置的效果。

保留原反馈格式与步号校验：模型判valid则不调用R；不合格式的首错步号仍拒绝；截取后前缀非法则保留失败候选。没有用真实首错位置修正模型反馈。执行器只用于该组的指定反馈和最终评分。

## 测试结果

候选ID/OOD各100条原非法路径。每格为成功率/最优率，分母均为100，不以成功样本作为最优率分母。

|反馈|回退K|ID成功/最优|OOD成功/最优|选择说明|
|---|---:|---:|---:|---|
|model|0|20%/20%|28%/20%|原Part2基线|
|model|1|24%/24%|44%/43%|开发选择|
|executor|0|94%/68%|92%/64%|原Part2基线|
|executor|1|91%/69%|92%/71%|开发成功不降约束|
|executor|3|89%/84%|90%/82%|开发最优率优先|
|executor|36|88%/87%|88%/87%|全丢前缀参考，非该组开发选择|

回退1步的执行器方案在开发集满足成功率不降，但测试ID仍下降，因此这个约束没有泛化保证。不能把它称作测试安全方案。

全部K在原29条生成失败上，模型反馈与执行器反馈修复均为0%，原200环境完整成功85.5%、最优85%不变。原因是在相同状态和目标下，普通策略仍作相同选择，回到旧轨迹任意位置仍可进入同一循环。

结论：仅改切点能改善受扰动候选，但不足以解决自身策略的确定性循环。Part2原始K0保留为基线；回退应作为Part3改进/消融报告，而非覆盖原对照。对于最优率目标，回退3步的开发选择有收益但牺牲测试成功率，应完整报告。
