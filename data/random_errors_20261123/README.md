## 执行与评测口径

`label/reason/step/trace` 沿用项目原有首错即停止的执行器。双错的第二处错误由单独的审计回放定位：非法动作被拒绝且位置不变，继续检查剩余动作，最后只检查一次 EOS。`audit_events` 是该审计回放的结果，不是原执行器实际执行到第二处错误的轨迹。未修改项目执行器，也不将两次截断算成两次未到终点。

双错中的未到终点只发生在 EOS，因此其首错标签必然来自另一种错误；应使用 `error_pair` 核对组合配额。未到终点的首错位置仍为候选动作数加一。

本次仅交付错误候选，未附合法控制。适合评估错误检出、首错、类型与修复；不能单独用于估计合法路线误拒率。将 `grid` 和 `candidate` 交给模型，答案、参考路线、错误类型组合和审计字段仅用于离线评测。

## 随机性与隔离

地图、起点、自避随机路线和终点、错误位置、非法动作词及行顺序均通过随机采样产生，不使用固定地图或路线模板。种子来自操作系统熵并记录于清单，支持复核。按配额进行条件采样，不声称在所有可能地图上均匀分布。

400 条样本使用互不重复的布局；与构造时扫描的旧数据及最新配对状态库无精确布局重合。未声明旋转／镜像形状完全隔离。

生成和审计脚本保留原工作区路径约定，依赖相应版本的 `ppnl` 源码、官方执行器和排除布局文件。它们不是在任意目录直接可运行的独立包；迁移机器时需调整这些路径。原始清单和源码不因发布而重写。
